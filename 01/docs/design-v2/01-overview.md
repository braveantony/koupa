# 1. 一頁看懂

## 1.1 這個階段在做什麼

一間手搖飲料店要替點餐系統加上「售完標示」，所以系統要升級。升級的過程中，客人的訂單可能送不出去、叫號螢幕可能漏掉已完成的號碼、客人重送可能變成點兩次。

這些問題大多來自同一件事：**一份程式要被關掉時，「叫入口別再送單過來」和「叫程式準備關機」兩件事會各自進行，彼此不會等對方完成。**

```
程式 1 要被換掉
   ├─► ① 通知系統入口：別再把訂單送給程式 1   （要一點時間才傳到）
   └─► ② 通知程式 1：準備關機
          │
          ② 比 ① 先生效 → 入口還在送單給正在關的程式
```

學生會先觀察升級時可能出現的這三種問題，接著一步一步加入修正，用數字比較效果，並從時間線找出問題可能發生的時段，根據紀錄解釋原因；證據不夠時就標成「未知」。實際出現哪些問題、改善多少，以量測結果為準。

## 1.2 系統長什麼樣子

```
 客人手機          店員平板          叫號大螢幕
 （點餐）          （按完成）        （一直連著）
    │ 短連線          │ 短連線           │ 長連線
    └────────────────┼──────────────────┘
                     ▼
                 系統入口
                     │
          ┌──────────┼──────────┐
          ▼          ▼          ▼
   處理訂單的    處理訂單的    處理訂單的    ← 同一個程式同時跑 3 份
     程式 1        程式 2        程式 3
          └──────────┼──────────┘
                     ▼
                  資料庫
```

- **短連線**：點餐時，手機送出訂單，等系統回傳號碼牌；拿到結果，這次請求就結束了。（本文說的「短連線」指這種很快就完成的請求，不管底下的網路連線有沒有被重複使用。）
- **長連線**：叫號螢幕一直連著系統，隨時等新的叫號；斷線時會自己重新連上。

升級時，系統會一份一份把舊版程式換成新版。被換掉的那一份程式，正在處理的訂單和連著它的叫號螢幕，都可能受到影響。

## 1.3 升級時可能出的三種問題

**問題一：訂單送不出去（短連線）**
```
1. 客人按「送出訂單」
2. 入口還不知道程式 1 要關了，把訂單送給它
3. 程式 1 已經在關機，客人看到「送出失敗」
```

**問題二：螢幕漏掉叫號（長連線）**
```
1. 大螢幕連在程式 1 上，顯示到 0057 號
2. 升級時程式 1 被關掉，大螢幕斷線
3. 斷線這幾秒，0058、0059 號做好了
4. 大螢幕重新連上 → 螢幕漏掉 0058、0059 號
```

**問題三：重送變成點兩次（短連線）**
```
1. 客人送出訂單，店裡已經收到（0058 號）
2. 號碼牌還沒傳回手機，連線就斷了
3. 客人看到「失敗」，再送一次
4. 店裡多一張 0059 號 → 同樣的飲料做兩份
```

## 1.4 怎麼修：五個步驟

先部署什麼都沒處理的版本，觀察升級時會不會出現問題，再一步一步修。每一步解決一類問題，必要時會一起調整相關設定：

| 步驟 | 做什麼 | 想解決什麼 |
|---|---|---|
| 0 | 什麼都不做 | 先看問題有多嚴重 |
| 1 | 程式被關掉前，先等幾秒 | 系統入口還在把訂單送給快要關掉的程式 |
| 2 | 程式被關掉前，先把已經收到的訂單處理完，並請大螢幕改連其他程式 | 訂單送不出去、大螢幕被突然切斷 |
| 3 | 大螢幕重新連上時，補回漏掉的叫號 | 螢幕漏掉叫號 |
| 4 | 客人重送時，認出是同一張單 | 重送變成點兩次 |

另外有一個獨立的小實驗：觀察大螢幕為什麼會在沒有升級的時候斷線。

## 1.5 怎麼比較效果

每一步都用量測工具 **Rush Hour** 模擬下午茶尖峰：一大群客人一直點餐、店員一直出餐、3 台大螢幕一直連著，同時讓系統升級一次，最後印出成績單：

```
┌──────── Rush Hour 成績單（虛構範例）────────┐
│ 量測方向：v1 → v2（升級）                   │
│ 訂單：                    1,200 張          │
│ 第一次送出沒有成功回應：     37 張          │
│   其中重試後仍沒有成功回應： 12 張          │
│ 重複訂單：                    4 張          │
│ 大螢幕漏號：   螢幕 1：5 個                 │
│                螢幕 2：0 個                 │
│                螢幕 3：3 個                 │
└─────────────────────────────────────────────┘
```

為了讓數字可信：

- **每一步量 5 次**，看範圍，不只看一次的結果；
- **兩組對照**：不升級時必須沒有觀察到問題；升級但不加任何修正（步驟 0）時，必須量到至少一種問題。兩組有一組不成立，這次的比較就不算數；
- **時間線**：每次量測都附一條時間線，把入口、程式和每張單的紀錄排在一起，看問題可能發生在哪個時段；證據不足的地方會註明；
- 有些問題要在特定的一瞬間才會發生，例如「訂單剛存好、號碼牌還沒傳回去」。這種情況由講師用測試工具刻意製造出來示範，不靠運氣碰到。

如果有結果還不能判定，成績單會另外列出「未知」的項目，不會把它算成 0。

學生每一步都先猜結果，再看成績單和時間線，最後解釋為什麼。成績單上的 0 代表「這一次沒觀察到」，5 次的彙整表全是 0，也只代表「這 5 次都沒觀察到」，不代表「不會發生」。
